# Shane Holloman • CV

A single-page CV built with Mintlify. The homepage includes a profile, expertise,
work history, studies, and education.

## Application structure

All authored application code, build tools, and tests are TypeScript. Strict
checking includes every source file, with unused locals and parameters rejected.
Zod validates data crossing runtime boundaries.

```text
src/
  client/       Header, search, icons, Aria UI, and Entity animations
  server/       Subscription auth, voice delegation, knowledge, HTTP service, gateway
  shared/       Zod contracts and activity calculations
tests/          Offline TypeScript tests
tools/          Development, build, release validation, and maintenance utilities
dist/server/    Generated Bun server bundles and source maps (ignored by Git)
dist/client/    Generated browser bundles, CSS, and SVG assets (ignored by Git)
dist/manifest.json  SHA-256 hashes of the client and server artifacts
header.js       Generated browser bundle committed for Mintlify
```

`bun run dev` builds and watches browser TypeScript and runs the local services.
It starts Mintlify against a temporary content directory outside the repository,
containing only the CV, configuration, browser bundle, CSS, and two SVGs.
The local CLI scans JavaScript recursively and does not apply `.mintignore` to
that scan, so server distributions must stay outside its preview directory.
Only changed website assets are synchronized; release builds and private data
cannot trigger preview reloads or get injected into the browser. The temporary
directory is removed when development stops. Mintlify's CLI runs on Bun too.
`bun run build` is the release gate: strict type checking, source audit, lint,
format validation, offline tests, browser and server bundling, and an offline
smoke test of the built server artifacts through the gateway. That smoke test
checks the complete CV, a typed answer, browser assets, and artifact hashes.
The client distribution contains this application's browser enhancements;
Mintlify builds and hosts the surrounding CV site. Mintlify loads custom
JavaScript from its published content directory; `header.js` is a generated copy of
`dist/client/header.js`. The NAS serves its browser assets directly from
`dist/client`; editable JavaScript does not remain at the site root.
The Docker image packages both distributions and runs
`bun dist/server/aria-runtime.js`; application source and tests are excluded.
Neither building nor offline validation needs OpenAI credentials.

When repository Actions is enabled, the checked-in workflow repeats this release
gate and verifies the committed Mintlify assets match their TypeScript sources.
Publishing through Mintlify and the NAS Docker pipeline does not depend on Actions.
`.mintignore` excludes application source,
server artifacts, tests, and tooling from Mintlify's published content.

## Content

Edit `index.mdx` for CV content, `style.css` for layout and typography, and
`docs.json` for site settings and contact navigation.

Typography uses Montserrat at weight 800 for the name and 900 for other headings,
with Roboto at weight 400 for body text and 700 for bold text.
The hero name's dot is a circle whose diameter follows the Entity's rendered
stroke thickness. It shares the Entity dot's ten-colour palette, fading for four
seconds between colours every 6.5 seconds. At rest, both dots share one animated
colour and 0.7 opacity. Connecting a conversation restores the Entity dot's
existing background activity response. Cycling pauses in hidden tabs and is
disabled when the visitor prefers reduced motion.
Site accents are monochrome dark gray (`#737373`) in both themes. The navbar
and browser icon inherit that gray. Color is confined to the Entity and the
hero name's dot; their shared fallback is the palette's emerald green.

`favicon.svg` is the shared source for the browser icon and navbar mark.
It contains Lucide's `FingerprintPattern`, imported and generated by
`tools/generate-logo.ts`, with a `currentColor` stroke and dark gray fallback.
The navbar uses a CSS mask to inherit the highlight color;
`src/client/icons.ts` applies that same computed highlight color to the browser tab
icon whenever the theme changes. Change the imported icon in `tools/generate-logo.ts`
and run `bun run build:icons` to update the shape everywhere. The header logo is
20px; other header icons are 16px.

The header section, profile, and contact links use generated `header.js`. Its source,
`src/client/header.ts`, imports icons and the SVG renderer directly from
the current `lucide` package. GitHub uses `CodeXml`, LinkedIn uses
`ContactRound`, and contact uses `Mail`. Theme controls, mobile menu controls, and
link arrows also use Lucide. The icons render as inline SVGs, inheriting the active
highlight color. Search, Aria, and the social icons are configured in `docs.json`
so the desktop header renders them in its initial HTML. CSS fixes control and
text-link dimensions before hydration and font loading; the mobile header also
reserves Aria's slot from first paint. Other header icons match the 16px text size, with 40px item heights
and 24px gaps.
The compact mobile menu includes system, light, and dark preferences with a
selected state, three section links, and one row for search, Aria, and social
icons. It uses Mintlify's persisted theme preference and storage listener so
desktop controls, OS preference changes, and reloads stay synchronized.
Choosing search or Aria closes the navigation before opening its conversation
or search dialog. Experience entries put the role first, then dates, company,
and description.
The library license is included in `LICENSE.lucide`.

Section headings and the browser favicon share `src/client/icons.ts`: fingerprint
for Profile, layers for Expertise, briefcase for Experience, book for Studies,
history for Earlier & independent work, and graduation cap for Education. These
decorative icons are 16px and inherit the heading color.

The Lucide search control opens a local section search implemented in
`src/client/search.ts`. It indexes the rendered CV content, ranks role and company
matches ahead of body mentions, and links results to stable anchors in `index.mdx`.
Search results use Lucide's `ChevronRight`; Mintlify's built-in icon library is
also configured as Lucide in `docs.json`.
Selecting a result closes the dialog and scrolls to that entry below the header.
It supports keyboard navigation, Command/Ctrl+K, and works without a Mintlify login.
Run `bun test tests/search.test.ts` to check search matching and ranking.

Build and validate the release after changing source:

```sh
bun install --frozen-lockfile
bun run build
```

The build minifies whitespace and identifiers. Generated bundles include a lint
marker because they contain third-party Zod code. `bun run lint` checks the
authored sources with warnings treated as failures. `bun run build:icons` and
`bun run build:aria-preview` remain shortcuts for a browser-only development build;
production packaging uses `bun run build`.

Content was adapted from
[`shaneholloman/cv` • `RESUME.md`](https://github.com/shaneholloman/cv/blob/fdb7da300ef429de7e236ba81e07b972ae213175/RESUME.md).
Education entries follow that source, without inferring degree
completion. Content updates are manual.

## Preview and validate

### Local Aria development

Run `bun run dev` to start the Mintlify preview at `http://localhost:3000` and
the local Aria service at `http://127.0.0.1:8791`. Click the Aria icon immediately
after search, then **Ask Aria**. Cove is fixed as the default voice,
and the voice selector is temporarily hidden. The component appears on
localhost, the live Mintlify CV, and the NAS-hosted combined preview.
It uses the current theme, Montserrat headings, Roboto body text, and the supplied Aria mark in
`aria.svg`, with no background
or fixed stroke color. Controls use imported Lucide icons.

The hero Aria Entity is a voice-only entry: click to start, click again to end. It
keeps the page visible and does not render captions. The header icon opens the
conversation panel. Opening the panel during a hero call shares that call;
closing the panel returns to voice-only mode. Calls started in the panel end
when the panel closes.

The entity preserves native Aria's 45 ms attack, 260 ms release, 220 ms background
pulse decay, speech normalization and event-magnitude response. The centre ring
meters the visitor, the outer arcs meter Aria, and the top dot follows Luna's
real streaming activity. The middle arcs stay steady. Waveform analysis
leaves the direct audio path intact. Colours follow the current
theme. The desktop entity is 25% taller than the name-to-summary text span and
centred vertically across that span, with a small leftward offset. Mobile uses
a 64px mark centred beside the name, with a 24px column gap.
Hover reuses the uic.nz entity treatment, with its glow opacity halved: a white 10 px glow at 0.3 opacity,
0.5-second ease, opacity 0.7 to 1, and scale 1.005. Resting strokes use the shared
muted gray in both themes. Only visible strokes activate
it; a 50 ms release delay bridges gaps. The top dot picks from the same ten
colours and transitions over 0.4 seconds. Keyboard focus gets the same treatment.
The hover highlight blends back into the live voice levels over 0.5 seconds on
exit, rather than switching stroke colours abruptly. The selected dot colour
stays set until its contribution has faded out. Voice levels are not delayed
by CSS stroke transitions.
Desktop voice metering uses the original 256-sample waveform analyser on every
animation frame, with the original normalization, 45 ms attack, and 260 ms release.
The analyser outputs are unconnected: they read the streams without creating
another speaker-output branch. The analysis context opens after playback signals
`playing`, using the microphone capture sample rate.

Mobile devices temporarily skip waveform analysis entirely, including creation
of the analysis AudioContext. This includes iPhones, iPads (also in desktop mode),
and Android devices. Device detection is independent of viewport width, so a
narrow desktop window retains desktop waveform analysis. The Entity remains
visible with its resting effects and Luna activity; its voice rings do not react
to speech on mobile. While connecting or in a call, the hero Entity gently
breathes between 80% and full opacity, taking one second each way. Reduced-motion
preferences disable that pulse. A real iPhone listening test with no analysis context was
completely clear after earlier analyser-enabled calls crackled. Mobile waveform
analysis can be revisited separately and must pass an iPhone listening check
before publication. Desktop emulation cannot validate mobile audio quality.

Playback remains in a separate audio element in the document body, including
during hero-only conversations. During a call the Entity uses full opacity;
its resting gray and hover treatment remain separate. Echo cancellation, noise
suppression, and automatic gain control remain enabled on every platform.
Audio diagnostics are hidden on normal visits to both deployed sites. Explicitly
append `?aria-audio-test=1` to a local, NAS preview, or production URL to show the
test controls in the header Aria panel. Reports remain in the browser and exclude
audio, transcripts, credentials, and network addresses. This opt-in does not
bypass the mobile waveform fallback; mobile calls still create no analysis
AudioContext. Desktop diagnostic controls can suspend analysis or skip it for
the next call without changing the live connection or microphone processing.

Aria's voice agent has one application control tool, `end_conversation`, using
the same strict client-delegation envelope as the native Aria app. Its prompt
limits this to an explicit goodbye or request to end, not an ordinary thank-you,
a quoted example, or a follow-up question. The tool ends only the caller's voice
session. It waits for farewell output and playback completion, with a short
WebRTC drain allowance for the subscription transport's turn-complete event.
A 15-second fallback prevents a missing completion event from leaving the call
open. The browser releases its microphone and closes the conversation panel;
the CV stays open. Luna retains only its approved knowledge lookup tools.

A successful voice connection saves only `aria.hasSpoken=1` in browser local
storage. Later calls from that browser request a welcome-back greeting. Failed
connections do not set the flag. This is a local greeting preference, not verified
caller identity or cross-device recognition, and stores no audio or conversation
history. Private browsing, clearing storage, or switching browsers can reset it;
a shared browser can show the same welcome to another person.

Aria uses your existing **ChatGPT subscription login**, read by the local service
from Codex's auth store. Sign in or refresh that login with `codex login`.
The prototype never uses an API key and never sends your OAuth credentials to
the browser. The subscription Live transport follows the established Aria
voice application's authentication and WebRTC call contract. The control
connection uses Aria's subscription Live caption and client delegation events.
Luna supplies grounded answers; OpenAI Live handles the spoken conversation.
Public visitor OAuth is a separate next step. The NAS service uses the owner's
dedicated subscription login, with two concurrent voice sessions, a five-minute
session limit, two concurrent text requests, and 40 requests per ten minutes
across the service.

Application source, tests, and tooling are TypeScript. Development runs source
with Bun 1.4.3; releases run bundled JavaScript built by Bun. TypeScript uses strict
checking, an ESNext target, Preserve modules, and Bundler resolution. Zod validates visitor requests, provider events, authentication data,
and knowledge-tool arguments. Its schemas also supply the function tools'
JSON Schema definitions.

The local server converts the complete `index.mdx` resume into Markdown,
preserving headings, lists and links. It wraps the Markdown in XML-encoded
sections and gives the full resume to both agents up front. There is no second
resume to maintain. Add approved `.md` and `.txt` background files to ignored
`data/knowledge/`, or set `ARIA_KNOWLEDGE_DIR` to another directory. These files
do not enter the browser bundle. Only add material Aria may disclose to visitors.
Approved knowledge is exclusively about Shane's biography, career and projects.
Do not put deployment notes, hosting hardware, network topology, authentication,
or application internals in this directory. Neither agent receives runtime
configuration or operational documentation. For questions outside Shane's
background, both explain their limited informational access naturally: they
have his resume and one directory of approved background information. They do
not frame this as a refusal or imply they are withholding secrets. Infrastructure
work in Shane's resume remains in scope.

Aria receives a supplemental source index, not all supplemental bodies, and
answers routine resume questions directly. It delegates supplemental lookups
or deeper analysis to Luna. Luna receives the resume, source index, question,
and up to eight prior delegated Q&A pairs, plus these read-only tools:

- `search_knowledge({ query })`: returns matching approved source IDs and excerpts.
- `read_knowledge({ source })`: returns one complete approved source. `resume`
  rereads the full resume; other IDs come from the source index or search.

Tools operate on an allowlisted in-memory snapshot. They cannot browse, run
commands, read arbitrary paths, follow symlinks, recurse into directories, write
files, or access credentials. Tool rounds share a 45-second deadline, with at
most five model calls and twelve tool executions per answer. Encrypted reasoning
and function-call IDs are replayed across the stateless model calls.

```text
index.mdx -> Markdown -> XML resume + supplemental index
                         |                         |
                    Aria voice                 Luna reasoning
                    at session start           on each delegated question
                         |                         |
                  direct CV answer       search_knowledge / read_knowledge
                         |                         |
                         +<----- grounded answer --+

Browser <========== direct WebRTC audio ==========> OpenAI Live
Local Bun service: auth, context, delegation, lookup and captions
```

New voice sessions capture a fresh knowledge snapshot. Typed requests reload
the files; delegated voice questions use their conversation's original snapshot.
Run `bun run inspect:knowledge` to write the exact frontloaded context to ignored
`data/aria-context.xml` for review. Supplemental file bodies are absent from that
file until retrieved by a tool.

Microphone access begins only after starting a conversation. Mute disables
its audio track. Ending the conversation or leaving the page releases microphone
capture and playback. Closing a panel-started conversation also ends it; closing
the panel during a hero-started call returns to voice-only mode. A conversation ends after five
minutes. Session context stays in memory; the service does not save transcripts.
It binds to loopback and accepts local Mintlify origins. The NAS runtime also
accepts the live CV and its configured HTTPS service origin through the gateway.

Use `bun run dev:aria` to run just the voice service. `bun run check` runs strict
TypeScript checking, linting, and offline tests, including retrieval boundaries,
Zod validation, function-call replay, cancellation, and lookup limits. Use
`bun run build` before a release. Changes remain local until
explicitly pushed to Mintlify and deployed to the NAS.

`bun run test:live` explicitly exercises both knowledge tools through the local
subscription login. It uses a temporary supplemental source containing approved
career facts, checks Luna searches and reads that source, and removes it afterward.
It calls OpenAI and consumes subscription usage; offline tests do not.

### NAS Aria workflow

Publishing changes involves two destinations: push the checked-in browser bundle
and CV to GitHub for Mintlify, and deploy a locally built image for backend changes.
The NAS does not automatically deploy from GitHub. The image includes `index.mdx`,
so CV edits also need a refreshed image to update Aria's resume context.
Supplemental knowledge lives outside the image in persistent `data/knowledge/`;
adding approved Markdown or text files there needs no image build. New voice
sessions and typed requests pick up those files; existing voice sessions retain
their original knowledge snapshot. The persistent subscription login is preserved
when the container is replaced.

Build on the Mac for the Synology's Linux x86-64 architecture. Never build on
the NAS. The Compose project has no build directive and uses its own directory,
`/volume1/docker/shane-cv-aria`, separate from Lina and other services.
The runtime is Bun 1.4.3, pinned by image digest. Aria and its gateway run on Bun;
the bundled Codex CLI supplies the headless login flow. Run `bun run test`
to check the service, token renewal, SSE and WebSocket proxy on Bun.

```sh
bun install --frozen-lockfile
bun run build
docker buildx build --network host --platform linux/amd64 -t shane-cv-aria:preview --load .
mkdir -p /Volumes/tank/build-artifacts/shane-cv-aria
docker image save --platform linux/amd64 -o /Volumes/tank/build-artifacts/shane-cv-aria/preview.tar shane-cv-aria:preview
```

Transfer the image archive and `compose.yaml` to the NAS project directory.
This follows Lina Muses' existing deployment pipeline: a ready image, a standard
Compose file, a private `.env`, and persistent `data/`. No Container Manager
project wizard or NAS image build is needed.

Create `data/auth` and `data/knowledge` there, owned by UID/GID 1000. Keep the
auth directory mode 700 and the project directory private. Create an empty
`.env` with mode 600; it is reserved for runtime overrides. The Compose file
already supplies the preview origin and other non-secret defaults.

Load the ready image and start only this project:

```sh
cd /volume1/docker/shane-cv-aria
sudo /usr/local/bin/docker image load -i preview.tar
sudo /usr/local/bin/docker compose up -d --no-build --no-deps site
sudo /usr/local/bin/docker compose ps
```

To sign in **on the NAS**, run:

```sh
sudo /usr/local/bin/docker compose exec site bun /usr/local/bin/codex -c 'cli_auth_credentials_store="file"' login --device-auth
```

Open the displayed OpenAI link in your browser and enter the one-time code.
Device code login may need enabling in ChatGPT's security settings. The login
command runs inside the existing container and writes credentials directly into
the NAS's `data/auth` directory.
It does not copy or mount the Mac's login. Aria renews this dedicated login
before token expiry and saves rotated tokens with mode 600. Repeat the login
command if access is revoked or OpenAI requires another sign-in. The image and
Git repository contain no subscription credentials.

The existing `yoyo` Cloudflare Tunnel routes `aria.shaneholloman.dev` to
`http://20.0.0.3:18082`, matching Lina Muses' public-domain deployment pattern.
Cloudflare provides public DNS and HTTPS. The CV stays on Mintlify at
`shaneholloman.dev`; only Aria's API runs on the NAS. No Cloudflare Access login
is needed for this public hostname. The existing `*.yoyo.io` Access policy is
unchanged.

The gateway accepts only its configured hostname, trusted LAN/container source
addresses, and browser requests from the CV or its own origin. It strips
cookies and authorization headers before forwarding to either upstream.

`aria.yoyo.io` belongs to an existing machine at `20.0.0.41`. Do not repoint it
at the CV service. If the temporary Mac resolver override from the earlier
preview was installed, restore normal machine-name resolution with:

```sh
sudo /bin/sh /Volumes/tank/git/sources/shaneholloman/docs/tools/restore-aria-machine-dns-macos.sh
```

This removes only the exact `/etc/resolver/aria.yoyo.io` rule installed during
preview and flushes the Mac DNS cache. No Mac, iPhone or UniFi DNS customization
is needed for the public Aria service.

The NAS preview fetches the published CV from Mintlify and adds its own Aria
assets after Mintlify initializes its custom header, preserving React hydration.
The preview claims its own Aria controller before the hosted browser bundle runs,
then waits for Mintlify hydration before adding interface elements. This lets a
NAS candidate be reviewed independently of the public CV.
Preview analytics and CSP reports are acknowledged locally rather than sent to
the live CV's analytics. `/aria-api/` routes to the NAS voice service over loopback. Mintlify
remains the CV host. The Mac and its development server are not part of this
runtime path. Open `https://shaneholloman.dev` or the combined preview at
`https://aria.shaneholloman.dev` on iPhone. Allow microphone access after tapping
**Ask Aria**.

Additional approved knowledge belongs in NAS `data/knowledge/`. Both knowledge
and authentication survive container replacement. `restart: unless-stopped`
restarts Aria after a NAS reboot. To roll back this preview, stop only the
`shane-cv-aria` Compose project and remove its single tunnel/DNS route; leave
other projects and tunnel rules untouched.

Install the [Mintlify CLI](https://www.mintlify.com/docs/installation):

```sh
bun add --global mint
bun run dev
```

Check internal links:

```sh
bun run --bun mint broken-links
```
